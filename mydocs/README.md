## 命名与新增约定

**目录**

- 主题目录用 ASCII 全小写（`desktop-ui/`），规避 Windows / git 的路径编码问题。
- 目录内文件用中文名。

**文件**

- 目录入口固定用 `README.md`：编辑器与托管平台会自动识别渲染，是唯一例外。
- 其余文件统一格式 `<主题><用途后缀>.md`。
- 用途后缀三选一，按"文档回答什么问题"定：

| 后缀 | 回答的问题 | 内容特征 |
| --- | --- | --- |
| `地图` | 在哪 | 结构树、区域与文件对照、目录职责表 |
| `清单` | 有哪些 | 枚举型资产、要素全集、执行步骤列表 |
| `指南` | 怎么改 | 单点改造的行号级定位、动作链路、边界与注意事项 |

- **不带序号**：阅读顺序与优先级由本文件的「文档清单」维护，避免插入文档时全量重编号。
- 一个文件只讲一个关注点。属于同一关注点的细节不拆第二篇。

**新增一篇的步骤**

1. 在 `desktop-ui/` 建 `<主题><用途后缀>.md`。
2. 文件头部固定三行：`入口：../README.md`、相关专题交叉引用、权威规范（`DESIGN.md` / `AGENTS.md`）。
3. 在本文件「文档清单」表补一行。
4. 跨关注点的公共事实（进程分层、窗口体系、平台抽象、状态所有者）只写在 `架构与文件地图.md`；专题文件用链接引用，不复制内容。

## 维护规则

- 代码改动后同步对应文档：只涉及结构位置时改 `架构与文件地图.md`；只涉及某功能点实现时改对应专题文件。
- 行号引用会随重构漂移。改动被引用的文件时，顺手核对引用行号。
- 未验证的推断标注为「待验证」，不要写成结论。
